Candidate axes to think through (out-of-the-box, not limited to): exhaustive/guaranteed branch+rule coverage (not best-effort); recursion-depth strategy that still reaches deep-but-rare branches; constraint-aware / semantic-store-aware generation (valid-by-construction stimuli); shrinking/minimization of counterexamples; coverage-closure proofs (the generator itself proving it covered everything reachable); determinism + seed reproducibility; performance at scale; multi-profile/dialect awareness; targeted/biased generation toward user-specified rules; negative/invalid stimuli generation for robustness; parity between in-memory and generated-module stimuli; cross-parser generality (must stay parser-AGNOSTIC per [[feedback_ast_pipeline_parser_agnostic]]).

**Scoped lane — "generation-window / min-viable-depth" characterization (director-folded 2026-07-06, session #45, from the `PARSE-HARNESS.5.5` surprise).** A concrete capability-gap the rtl_const_expr corpus work surfaced sharply: the generator can *silently* produce ZERO samples for a grammar whose minimal derivation depth exceeds the requested `max_depth`, and it can *hang* on deep-precedence-cascade grammars whose expected sample size explodes super-linearly with depth. The gate's `[6,12,18]` depth ladder sat silently below rtl_const_expr's ~30-level floor → 0 corpus, diagnosed only by a hand-run CLI depth-sweep. Formalize this as three deliverables (decreasing value / increasing cost), all parser-agnostic:
  1. **`min_viable_generation_depth` — a linter property (highest value, lowest cost).** The height of the shallowest derivation of the start symbol, a simple fixpoint (terminal→0; seq→1+max of mandatory parts; alt→1+min over branches; `*`/`?`→0; `+`→N×inner) — essentially the "min-subtree depth" the witness planner already computes ([[project_witness_pass_per_target_depth_budget]]). Surfaced by `--lint-grammar`, it turns today's silent 0-corpus into a loud "this grammar cannot generate below depth D; your config tops at K." **This alone reduces the `.5.5`-class surprise to a one-line diagnosis.**
  2. **A super-linear-generation-cost linter WARNING.** The narrow-window signature is structural + detectable: a recursive nonterminal that reaches ITSELF ≥2 times within one expansion (self-embedding *with branching* — the `X := Y (op Y)*` cascade-quantifier shape stacked over N precedence levels). A warning class next to the existing left-recursion / shadowing / non-terminating checks: "expect a hang cliff; budget it + likely need a curated corpus."
  3. **A `--report-generation-profile` diagnostic.** The productized depth-sweep: the floor (from #1) + an empirical viable band per depth/seed within a step budget + the growth-class flag. This is the honest home for the *upper* window edge, which is NOT intrinsic — it is the grammar's growth class convolved with the step budget + seed, so it is a measured diagnostic, not a closed-form theorem.
  Deep grounding (per [[feedback_research_grounded_sota_no_trial_and_revert]]): this is the analytic combinatorics of random CFG derivation (Flajolet–Sedgewick generating functions — mean derivation size diverges when the grammar's generating function has a small radius of convergence). The SOTA generator-side *fix* (beyond diagnosis) is **Boltzmann sampling** (Duchon–Flajolet–Louchard–Schaeffer): size-targeted CFG sampling that sidesteps the depth-cap pathology — a candidate future generation MODE for cascade grammars, a bigger lift than the three diagnostic deliverables above. Homes: (1)+(2) in the grammar linter (static grammar properties — its job); (3) a stimuli/diagnostic report like the existing k-path coverage report.
