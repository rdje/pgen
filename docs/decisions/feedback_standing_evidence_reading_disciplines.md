# The standing evidence-reading disciplines

These ten bullets were carried in layer A (`MEMORY.md`) because each is about **how I read
evidence, measure, and publish** rather than about any one leaf. They are moved here verbatim on
2026-09-03 (`MEMORY-ARCH.7`): layer A is bounded by a line cap AND a byte cap, it had reached
**32 693 of 32 768 bytes**, and `MEMORY_ARCHITECTURE.md` §6 says a cap is never raised to land
content — the content is demoted. Layer A keeps one pointer to this record. Nothing below is edited;
every slice id and wiki-link in it is preserved (the no-loss control is in the owning leaf).

- ⛔⛔⛔ **KEPT IN LAYER A BECAUSE IT IS ABOUT HOW I READ EVIDENCE AND IT COST THREE PUBLISHED CLAIMS IN ONE SESSION (`-0160`): A VALUE LIFTED OUT OF A GRID, A LOG LINE OR A PROCESS LISTING ARRIVES WITH A *FRAME* ATTACHED — THE BOUNDARY, THE FILE, THE ROOT — AND THE FRAME IS THE PART I DID NOT MEASURE.** (1) a 12-point spawn grid: OK at 64 TiB, FAIL at 128 TiB, published as *"the first refusal is at 128 TiB = an 8 PiB host"* — bisected it is `2^46` = **64.000 TiB**, so the breaking host is **4 PiB**; a grid cannot locate a boundary. (2) a clippy warning citing `systemverilog_parser.rs:1582679`, published as a *"1.58 M-line"* file — `wc -l` = **1 709 231**; a line NUMBER is not a LENGTH. (3) a RELATIVE path in another process's `ps` line (`p='DEVELOPMENT_NOTES.md'`) resolved against MY root, published as *"a second Claude session is live in THIS repo writing a tracked live doc"* WITH a commit-safety mitigation — its cwd is `…/github/anvil`, `CLAIM-SHAPE-SHADOW-RUN` is an anvil tree `git grep` finds nowhere here, and PGEN's copy was untouched. ⛔⛔ **The refutation was in my OWN printed output** — `lsof | grep -c pgen` -> **0** — narrated past as *"the write has not landed yet"*. ⇒ **for every number in a finding, name the command that produced IT AND ITS FRAME; if the frame has no command it is not evidence yet.** → [[a-number-read-out-of-context-carries-a-frame-you-did-not-measure]]. ⭐ SPENT, not just filed: the 384 MiB boundary was about to ship as *"≈7 220"* off an accept-7000/reject-7600 pair (same error, one hour later) and was BISECTED instead; and the corpus diff's first cut compared `(sub-corpus, verdict)` MULTISETS in which two files swapping verdicts cancel — re-keyed on the PATH, with a RED control.

- ⛔⛔ **AND A PROCESS DEFECT WORTH MORE THAN THE SLICE (`-0160`): A DELIBERATE MUTATION MUST NEVER OUTLIVE THE TOOL CALL THAT APPLIED IT.** I left a RED-control mutation in a shipping source file with its revert deferred to a background job; reverting it promptly under a director challenge then overwrote the file **while its own build was reading it** — `CI-PARITY-GATE-ROT.32`'s torn-build hazard — so the control produced NO verdict and would not have been trustworthy if it had, and a 1 m 13 s build became 15 minutes of dependency recompilation with a test binary stalled at 80 KB RSS in `_dyld_start`. ⇒ **apply-test-revert in ONE uninterruptible step (a `trap`), or a throwaway worktree. Never a step you intend to take later.**

- ⛔⛔⛔ **KEPT IN LAYER A BECAUSE IT IS ABOUT HOW I READ A GREEN CONTROL — AND BECAUSE MY FIRST DIAGNOSIS OF IT WAS WRONG AND WAS PUBLISHED TO THE DIRECTOR.** `-0157`: a mutation on the MOST important lock (*the anchor must not track the derived default*; tracking it restores `.79`'s `rc 134`) came back GREEN. I diagnosed *"the two anchors are numerically identical at ≥16 GiB, so no assertion can tell them apart"*, opened `.87`(e) on it, and led my findings with *"a control that cannot fail on your host passes for that reason."* ⛔ **`-0158` REFUTED THAT IN ONE COMMAND**: mutated + `PGEN_PARSE_STACK_BYTES=536870912` FAILS (`left 768` vs `right 1536`), `=134217728` FAILS the other way (`left 3072`); unmutated under both envs stays green. ⇒ **the lock was ALWAYS adequate — my HARNESS ran one process configuration**, and in it the mutated program is SEMANTICALLY IDENTICAL, so the green was CORRECT not blind. ⭐⭐ **THE REAL RULE: a mutation is only a control where the defect it names can EXIST — so a green mutation is a question about the CONFIGURATION before it is a verdict about the lock; and when a control comes back green, FALSIFY THE EXPLANATION, not just the control.** I had a falsifiable story, did not spend ten seconds on it, and it was flattering — a limitation dressed as a discovery. `.87`(e) WITHDRAWN with its premise.

- ⛔⛔⛔ **THE RUNNING SERIES OF PRE-REGISTRATION FAILURES, kept in layer A because it is about HOW I MEASURE, not about a leaf. Each is a FRAME the prediction inherited instead of checking:** the **QUANTITY** (`-0126` — name which instrument reads it, and whether it reads the same thing the DENOMINATOR is made of); the **SENTENCE** (`-0125` — falsify the CLAIM, not the instrument); the **SET** (`-0127` — when you publish N findings, verify the GROUPING: that N is the whole population and the shared cause holds member by member); the **LIFETIME** (`-0128` — before predicting a thing is GONE, read its `Drop`); the **ESTIMATOR** (`-0129` — name min/median/max, or two of your own instruments will answer differently for the same run); the **BOUND** (`-0129` — a bound with an UNMEASURED TERM is not a bound, and a saturated result on every row is exactly when to look for the term you forgot); the **COUNT** (`-0130` — run the check on every COUNT in the artifact, not on the roster of claims; agreeing with yourself is not corroboration). ⛔⛔ **`-0131` ADDS TWO. (8) THE IDENTITY: a DECOMPOSITION of a total is a HYPOTHESIS, not an observation** — a size-class total has many decompositions, and the subset-sum search that named four `T=296` tables on `floor.sv` named three the process never allocated (the eight BODY inputs agree table for table, so the bands stand). ⛔ **A corollary I published the same day is WITHDRAWN by `-0132`**: I claimed `-0128`'s *4 of 8* was METHOD-DEPENDENT rather than wrong. It is not — `-0128` cited `t_math_synmul_mul.v` as its worked example and the strict method sees only ONE table there, so it cannot be the method it used; it was reading the attribution (5) and published 4. A MISCOUNT, like `-0130`(4). **(9) THE CONTROL'S SCOPE: a control validates the PROPERTY IT IS BUILT FROM.** My tape's first cut stamped allocations and releases on TWO DIFFERENT CLOCKS, so every succession verdict was meaningless — and its control (`live at instant I`) stays inside one clock per comparison and passes either way. ⇒ **a new property needs a new argument, never the old control run again.** ⚠️ `-0132`: the two-clock form was never committed, so that counterfactual is REASONED, not replayable — the card says so. ⭐ Caught by reading the instrument's own first output; NO pre-registered row predicted it or the identity finding — the honest reading of a 9-of-10 scorecard. ⛔⛔⛔ **AND `-0132` ADDS THE TENTH, WHICH IS THE ONE THAT COST A PUBLISHED FINDING: (10) PROVENANCE. *Why did the earlier author get that number* is a CLAIM, not context, and a CHARITABLE reconstruction is the most dangerous kind because being generous feels like rigour.** I reconstructed `-0128`'s 4 as a method artifact and published it; the refuting row was in the very table I published it with (column A disagreeing with B and C on exactly the input `-0128` cited). ⇒ **check a provenance claim against the artifact the earlier author CITED, never against plausibility.** ⛔ And a second from the same audit: **a document that DESCRIBES a guard's trigger TRIPS it** — three of the nine `promotion: declined (` tokens in the SV tree are now prose ABOUT the token, so `DOCTRINE-GAP-OWNERSHIP.19`'s first fix shape (diff-scoping) was insufficient and is corrected to require the token to HEAD a list item.

- ⛔⛔⛔ **THE TRANSFERABLE LESSON, kept in layer A because it is about HOW I MEASURE: AN ORACLE'S BLIND SPOT IS INHERITED BY EVERY CONCLUSION BUILT ON IT, AND A CLEAN REPLICATION CANNOT REVEAL IT.** `.61`(b) measured nesting as `()[]{}` depth — sound, cheap, and **structurally blind to the one shape that matters**, because a right-associative ternary chain has NO brackets. It read **22** where the same corpus holds **256**, and I re-ran that oracle in `.63` and got **22** again: replication confirms the INSTRUMENT, never its COVERAGE. ⇒ **before trusting a proxy metric, name one instance of the thing you are measuring that the proxy would score ZERO** — if you can construct it in a minute, the proxy is not measuring what you think, and a calm p99.9 (here **8**) is the most persuasive kind of wrong. ⭐ Paid twice more: my own `case_items` counter read **870** vs a real **569** (it counted `:` inside `[31:0]` slices) and was caught only by hand-counting before publishing, the residual reconciling EXACTLY as `default:`; and a cliff landing on a ROUND number in TWO unrelated families was CHASED, not classified, which is the only reason `.66` was found at all. → [[an-x-is-checked-by-nothing-claim-is-a-census-claim]], [[project_rtl_parsers_accept_any_rtl_no_limits_non_negotiable]]

- ⛔⛔ **NEVER MEASURE PEAK RSS ON A BUSY MACHINE — measured, `-0128`: a ladder run alongside a 10 GB LTO build read peak RSS −13.6 / −27.9 / −25.8 % LOW on exactly the three inputs peaking above ~1.9 GB, and within ±0.6 % on the other eight — silent, plausible, wrong. Caught only because `peak_live` (allocation-side) is DETERMINISTIC and RSS is not: byte-identical across both runs on 11 of 11. Nothing in the harness enforces idleness.**

- ⛔⛔ **A BACKGROUND JOB OUTLIVES THE SESSION THAT SPAWNED IT, AND ITS OUTPUT PATHS ARE TRACKED FILES — kept in layer A because it is about HOW I RESUME, not about a leaf.** This session opened on a dirty tree that layer A said was clean: an orphaned `chain.sh` from a DEAD session (scratchpad `d2751264`) was still running after 1 h 24 m and overwrote three tracked `.67`(c) artifacts at the script's DEFAULT tape threshold instead of the recorded `16384`, its log gone with the session. ⇒ **on resume, when the tree is dirty, `ps` for orphaned jobs BEFORE reading the diff** — I sampled the files twice and the sizes moved under me, which is the only reason I looked. ✅ RESTORED and PROVEN: `rehash_spike_report.py` re-derives the committed report BYTE-IDENTICAL from the restored tape. ⭐ The overwrite paid for itself — chasing its uniform `-1` found **`.76`** ([[an-x-is-checked-by-nothing-claim-is-a-census-claim]]): **`peak_live` INCLUDES THE PROBE'S OWN ARGV** (1 B per flag-value char, **2 B per input-path char**, decisive control `08192` vs `16384`), so it is NOT a pure function of the input — 0.004 % of the peak (the ladder's WORST case; 0.00003 % on the largest), immaterial to `.67`'s CLOSED bound, but it is the DETERMINISM property `-0128` leans on. ✅ `-0135` SELF-AUDITED it under a director challenge: NOTHING withdrawn — the published *"48 bytes unattributed"* caveat is CLOSED (adding a 19-char flag pair costs +67 B, removing a 21-char one −69 B ⇒ the SAME 48 = a fixed ~24 B per argv entry, so `peak_live = base + Σ(24 + len(arg))`), and provenance is now BYTE-IDENTICAL artifact evidence. ⛔ But the founding `-1` on 11 of 11 is RECORDED, NOT RE-DERIVED — the restore destroyed the second sample and the replay was killed so as not to leave an orphan at exit; re-run it first when `.76` opens.
