Mechanism (engine/generated-parser, NOT grammar/runtime-primitives/emit):

- Net effect: a `type_name` fact emitted by a *completed, successful* sibling rule is NOT visible to the next sibling's `has_fact` check. **ROOT CAUSE — DEFINITIVELY CONFIRMED 2026-05-19 (memoization unsoundness for context-sensitive rules).** The generator (`ast_based_generator.rs` ~1678) wraps every `is_recursive` rule in `memoized_call`; `memoized_call` (~4349) uses `let key = (rule_id, self.position);` — **NO semantic-state component** — and on a memo HIT returns the cached node OR cached **FAILURE** WITHOUT re-running the body / re-evaluating predicates. Trace of `module m; typedef int my_t; my_t [3:0] x; endmodule` proves the smoking gun: rules `CLASS_TYPE`(170)@pos17, `ATTRIBUTE_INSTANCE`(71)@pos0 (stale failure reused 14×), `PARAMETER_VALUE_ASSIGNMENT`(710)@pos32, `TYPE_REFERENCE[_SV_2017]`(997/999) are each BOTH "Memoized failed result" AND later re-served as a "cached failure" hit at the SAME (rule,pos). `class_type`/`type_reference` are on the `data_type` disambiguation path and their outcome depends on `@predicate has_fact(type_name,…)`. So: predicate-gated rule tried at P BEFORE the typedef fact exists → fails → failure cached at (rule,P); re-reached at P AFTER the typedef commits the fact → memo HIT returns stale failure, predicate NEVER re-evaluated. Classic Packrat unsoundness: memoizing on (rule,position) is valid only for context-FREE rules; a rule gated by mutable semantic facts is context-SENSITIVE and must not be (or must key on semantic state, or must not cache failures).
