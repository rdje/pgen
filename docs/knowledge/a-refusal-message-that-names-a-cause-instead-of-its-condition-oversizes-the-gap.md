**An error message is read as a description of the world. Write one that names a cause you inferred
rather than the condition you tested, and every reader inherits your inference as a fact.**

PGEN's certificate-coverage report needs to replay generated witness samples through a real parser, so
it refuses when it cannot. The predicate is narrow and exact:

```rust
if !parser_registry::supports_parse_and_cover(&grammar.grammar_name) {
    anyhow::bail!(
        "certificate-coverage: no generated parser is registered for grammar '{}' — cannot \
         verify reachability witnesses through a real parser (Phase H wires more grammars)",
        grammar.grammar_name
    );
}
```

`supports_parse_and_cover` tests one thing: **is this registry row's `parse_and_cover` field `Some`?**
The message says something much larger and different: *no generated parser is registered.*

For `ebnf`, `return_annotation` and `semantic_annotation`, the second statement was false. All three
had a registry row under their own name. All three had a working `parse_sample`. All three generated
artifacts already exported the whole coverage API, because codegen emits that instrumentation
unconditionally. One optional struct field per family was unset.

## Why the wording, not the gap, is the defect

A gap costs what it costs. What the message changed was **how the gap was priced by everyone who read
it** — and the pricing is what decides whether anyone picks it up:

| what the reader concluded | what was true |
|---|---|
| these families have no generated parser | they have one, registered, under that name |
| wiring them means building a parser | wiring them means setting a field |
| this is a Phase-H-sized project | it is an afternoon |
| the coverage numbers are unknown-because-unbuilt | they are unknown-because-unasked |

The parenthetical made it worse by sounding like a schedule: *"(Phase H wires more grammars)"* reads as
*a plan exists and this is on it*, which is an invitation to move on. Every reader who moved on was
being reasonable about the message they were given.

The cost was not the three fields. It was that three families sat outside the instrument while a
project-wide criterion — *every existing parser certificate-clean with `UNKNOWN`=0* — was tracked as
one family away from met. When the field was finally set, the three families reported **71 uncertified
rules**, and the criterion turned out never to have been met at all. A family outside the instrument
reports nothing, and **nothing is not zero**.

## The rule

**State the condition. Let the reader infer the cause.**

```rust
// The condition, and where to look:
"certificate-coverage: grammar '{name}' has no `parse_and_cover` adapter registered \
 (parser_registry::GENERATED_PARSER_REGISTRY) — witnesses cannot be replayed through a real parser. \
 A generated parser MAY still exist for this grammar; this checks only the adapter field."
```

That message costs one extra clause and cannot be mistaken for an absent subsystem. Three tests it
should pass:

- **Could a reader locate the thing you tested?** "No parser is registered" points at codegen. "This
  table field is unset" points at the table.
- **Does it distinguish the cause you guessed from its siblings?** *Field unset*, *parser absent* and
  *parser present but broken* are three different jobs. One message covered all three and named the
  most expensive one.
- **If your guess is wrong, does the message become false?** This is the tell. A message that only
  describes its predicate cannot become false; a message that narrates a cause is a claim, and claims
  need evidence the guard does not have.

⛔ **The trap is that this failure is invisible from inside.** The guard is correct — it fires exactly
when it should, never spuriously, and no test can catch it, because the defect is in the *English*, not
the *predicate*. It surfaces only when someone finally distrusts the message enough to go and look, and
by then the mis-pricing has already bought however many months it bought.
