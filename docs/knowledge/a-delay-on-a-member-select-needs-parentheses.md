# A delay on a member select needs parentheses

**The clause.** `delay_control ::= # delay_value | # ( mintypmax_expression )` and `delay_value ::= unsigned_number | real_number | ps_identifier | time_literal | 1step` — IEEE 1800-2017 A.6.5 (`docs/systemverilog/2017/md/section-41-data-read-api.md:2141-2146`, `:948-958`), IEEE 1800-2023 the same (`docs/systemverilog/2023/md/section-Annex_A-normative-formal-syntax.md:2134-2138`, `:989-999`). A `ps_identifier` is `[ package_scope ] identifier`: no `.`. So `#setting.offset;` is not derivable and `#(setting.offset);` is. The UVM 1800.2-2017 reference library writes the former (`uvm_pkg_all_v2017_1_0_{dpi,nodpi}.svh`, inside `m_verbosity_settings` processing) and every tool compiles it — a tool extension, exactly the kind of spelling the opt-in tolerance profile exists for, and not in its closed list today (the eleven `tolerated_*` rules carry no delay shape). Measured with the interpreter: `#s.offset;` REJECTS at the `.` on `sv_2017`, `sv_2023` and `sv_2023_tolerant`; `#(s.offset);` and `#d;` ACCEPT on all three. The two corpus rows are pinned `must_reject` with the clause and the reproducer pair `invalid_delay_control_member_select.sv` / `control_delay_control_paren_member_select.sv`; the tolerance candidate is named in the pin for `.43`'s list.

**The flag is part of the key.** `t_langext_order.py` compiles with `+1364-2005ext+v`: every `.v` file of that test is Verilog-2005 by the test's own declaration. `module t_langext_order_sub(input do);` is then legal text for the `verilog_2005` lane (1364-2005's Annex B lists no `do`) and text the 1800 lanes must reject (`do` is a keyword in every 1800 edition — 2017 `section-41-data-read-api.md:3646`, 2023 `section-Annex_B-normative-list-of-keywords.md:68`). The row's `must_accept` from the `.58` owner map was the test's expectation read without its language flag; `SVPP-EXPANSION.6c.2` had ruled the same for slang's `verilog.v` by extension and intent. Pinned `must_reject`; the `.13c.2` reproducer `invalid_reserved_word_port.sv` already stood for it.

**The three outcomes of reading a must-accept the pipeline rejects.** (1) Text the standard does not derive → a `must_reject` pin with the clause and a reproducer (`.57a`'s rule: the standard outranks the tool). (2) The derived context's gap → routed to the context tree, nothing relabelled: `t_hier_block_import_sub{B,sub}.v` take their macros from `t_hier_block_import_def.vh`, which the driver compiles first through a `-f` command file behind `$TEST_ROOT`; `t_sv_cpu_code/rom.sv` takes `` `LDI `` from `program_h.sv`, a listed predecessor, while `rom.sv` itself is a `-y` library member compiled after the list (`SVPP-EXPANSION.4c.5`). (3) The unit's declaration barrier → routed to the library tree: `cpu.sv`, `pads.sv`, `pinout_h.sv` reject on typedefs declared earlier in `t_sv_cpu`'s own unit (`genbus_if.sv`, `pads_h.sv`), which no library pass exports for verilator's plain-file units (`SVPP-EXPANSION.6d.9`); `.57b`'s instrument is the one to tell "declared elsewhere in the unit" from "declared nowhere". A fourth, riding: the rejects-own-file census read `cpu.sv` as `residue` because the fact gate stops at the `;` of `T name;` rather than at the name — `undeclared_type_shape` now reads both.
