**A detector you build is an inference. A label the artifact carries is a statement.** Prefer the
statement — it is exact, it has no false-positive population to triage, and its author is the
authority on the question you are asking.

## The shape of the mistake

The question was: *which productions does IEEE 1800 define in its clause bodies that Annex A — the
only surface PGEN's grammar is extracted from — does not carry?* That reads like a
natural-language problem over 3.4 MB of prose, and it was attacked as one, twice:

1. **A textual differential** between Annex A and the clause syntax boxes. It reported **172**
   divergences on the 2017 edition. Nearly all of them were PDF→markdown conversion artifacts —
   captions swallowed into production bodies, page furniture spliced mid-rule, `production_
   identifier` split across a line break.
2. **A structural heuristic** over the shipped grammar: a production that names a nonterminal *and
   separately* names one of the things that nonterminal should already cover
   (`casting_type ::= simple_type | … | string | …`) is evidence the nonterminal is short. Real
   signal, but a ranked-candidate list requiring per-row adjudication.

The actual answer is one line of the standard's own typography:

```text
Syntax 10-5—Assignment patterns syntax (excerpt from Annex A)
Syntax 18-11—Scope randomize function syntax (not in Annex A)
```

IEEE had already done the classification, per box, in words, in the normative text. **304 / 60** in
the 2017 edition.

## Why this generalises past IEEE

Authored artifacts routinely carry their own metadata, and it is routinely ignored because it is not
where a programmer looks for structure:

- captions, footnotes and marginalia in standards;
- `@deprecated` / stability annotations in API references;
- changelog headers and `Since:` fields;
- the "generated by" banner that says which tool wrote a file.

The habit is one question asked *before* the first line of detector code: **does the artifact say
this about itself?** It costs a grep. Building the detector first costs the detector plus every
false positive it will ever produce, plus the standing obligation to maintain it.

## ⛔ The corollary that saved this census: do not key on a converted document's file names

The same PDF→markdown conversion that made the textual differential noisy also mangled the section
titles, and it did so *differently per edition*:

- the 2017 Annex A holds **zero** productions in `section-Annex_A-…-using-bnf.md` (50 lines of the
  front-matter list of annexes) and **736** in `section-41-data-read-api.md`;
- Annex F's formal-semantics metavariables are filed under `section-100-time-units.md`;
- the 2023 edition has both in sensibly-named files.

A census keyed on file names would have been confidently wrong on one edition and right on the
other — the worst possible failure, because the disagreement reads as a real difference between
editions. The caption carries the clause number IEEE printed, and the splitter cannot touch it.

## And the instrument must refuse rather than guess

The census exits non-zero on any clause-only production it cannot attach a caption to. On its first
run that surfaced seven single-uppercase-letter "productions" (`P ::= strong ( R )`) — Annex F
rewriting rules, not SystemVerilog syntax. A permissive instrument would have shipped them in the
worklist as seven mystery constructs for someone to chase. They are now a **declared** bucket with a
guard proving Annex A names no single-letter production in either edition, so the exception cannot
silently widen.
