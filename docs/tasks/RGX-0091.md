## Root cause (tool-backed, session #188)

- The 0086 gate `regex_parser_pgen_rgx_0086_embedding_version_consts_match_ledger`
  (`rust/src/embedding_api.rs:4646`) derives its expected value as the
  **max-by-release "Fixed in" cell over `PGEN_RELEASED_PARSER_BUG_LEDGER.md` table
  rows**. That oracle is sound ONLY while every release/contract bump is a bug-ledger
  row. The two missed bumps were NOT bug rows:
  - `PARSER-NEUTRALITY.1` (2026-07-20): release `1.1.104`→`1.1.105`, contract
    `1.1.106`→`1.1.107` — a mechanism-REMOVAL release, recorded in the contract doc
    identity + release highlights only.
  - `PGEN-RGX-0078-0212` (2026-07-21): contract `1.1.107`→`1.1.108` — a
    carrier-slimming contract bump, ditto.
  The ledger's latest regex row remains `REGEX-0113` ("release 1.1.104; contract
  1.1.106"), so the gate's derived expectation EQUALS the stale constants and passes.
  Verified locally: `grep` of the ledger tail (rows `REGEX-0112`/`REGEX-0113`) +
  the contract identity block (`1.1.108`/`1.1.105`) + the constants (`1.1.106`/
  `1.1.104`) + the JSON mirror (`1.1.106`/`1.1.104`).
- Classification: **mis-specified gate oracle** (incomplete source-of-truth), not a
  broken assertion. The authoritative declaration of "what versions is this tree" is
  the contract document's **Contract Identity block** — the surface downstream reads
  first — and the gate never consulted it.

## Fix design

1. Sync the three surfaces to the identity block: release `1.1.105`, contract
   `1.1.108` (spec-derived from the contract doc at HEAD, per
   `feedback_corpus_expected_from_spec_not_fix` — not copied from the report).
2. **Gate re-spec** (same file, spec-derived oracles, no hardcoded literals):
   - NEW `regex_parser_pgen_rgx_0091_embedding_version_consts_match_contract_identity`:
     parse the Contract Identity block of
     `docs/contracts/PGEN_REGEX_PARSER_INTEGRATION_CONTRACT.md` ("Contract version" +
     "Parser release version" bullets) and assert BOTH constants equal it. This
     binds constants to the authoritative declaration for EVERY bump class
     (bug-fix, feature, maintenance).
   - RE-SPEC the 0086 test to the relation that IS ledger-invariant: the ledger's
     max regex "Fixed in" release/contract must be **≤** the contract-identity
     versions (a bug row may never run AHEAD of the identity block; equality not
     required — feature bumps legitimately outpace the ledger). Keep the 0086 name
     (`..._match_ledger` → the assertion text explains the ≤ relation) or rename to
     `..._ledger_never_ahead_of_identity`; the implementation picks the clearer one
     and records it here.
   - The pre-existing `regex_parser_integration_contract_metadata_is_stable` test
     continues to pin the JSON mirror ↔ constants equality (it is what caught copy
     #3 in 0086).
3. **Red-before/green-after demonstration** (the report's verification note asks
   that the gate "demonstrably fires on a mismatch"): run the new identity test
   against the stale constants BEFORE the sync (must FAIL), then after (must PASS).
   Record both runs in the Verification Log.
