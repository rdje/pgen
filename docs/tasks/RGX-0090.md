## Goal

Fix `PGEN-RGX-0090` (downstream report
`/Users/richarddje/Documents/github/rgx/pgen-issues/PGEN-RGX-0090.yaml`): on a
cold clone (empty `generated/`) the documented downstream path
`make -C rust regex_parser_bootstrap` cannot complete at pin `960dddaa` — seed
step C is REFUSED by the `RGX-0078.5.i.1.t2` annotation-backend guard, the
refusal is swallowed, and the recipe dies later with the misleading
`No rule to make target '../generated/ebnf.rs'`. Also harden the stale-artifact
trap (a `generated/ebnf.rs` from an older pin fails the build with ~1,497 rustc
errors and no actionable message).

## Root cause (tool-backed, session #188 — reproduced in a scratch CARGO_TARGET_DIR without touching repo state)

Reproduction (no-`generated_parsers` `ast_pipeline` built into a scratch target
dir; seed steps B/C run against a scratch generated dir):

- Step B (`--emit-raw-ast-json`) → exit `0` ✓.
- Step C (`--generate-parser --debug --eliminate-left-recursion … -o ebnf.rs`,
  NO `--bootstrap-mode`) → prints `Error: REFUSED: return annotation
  '{type: "grammar_file", elements: [$1*]}' needs the generated annotation
  backend…` and **exits `1`** — the binary refusal is LOUD and NONZERO.
  (The report's sub-defect (1) "`ast_pipeline` EXITS 0 on the REFUSED path" is
  therefore MIS-ATTRIBUTED at the binary level: the `Err` propagates through
  `parse_return_annotation_ast` → `extract_rule_annotations` →
  `parse_rule_content` → `transform_from_raw_ast` → `main() -> Result<()>`,
  which exits nonzero. Verified: `stepC exit: 1`.)
- The REAL exit-0 swallow is the **Makefile seed compound**
  (`rust/Makefile` `regex_parser_bootstrap`): the whole seed block is ONE
  `@if [ ! -f … ]; then …; fi` shell invocation whose commands are `;`-chained —
  a failing step does NOT abort the compound, and the compound's exit status is
  the LAST command's (the `cargo build` rebuild, which succeeds) ⇒ make sees
  exit 0, continues to step D, and step D's prerequisite `../generated/ebnf.rs`
  is missing ⇒ the misleading `No rule to make target` — byte-for-byte the
  behavior RGX observed at the make level.
- Sub-defect (2) confirmed: the recipe's step C passes neither
  `--bootstrap-mode` nor the env opt-in, although the target's own design
  comment specifies a bootstrap-mode seed. With `--bootstrap-mode` added, the
  same scratch seed exits `0` and writes `ebnf.rs` (12,446,476 bytes) —
  verified. All `config.bootstrap_mode` switches in the pipeline are
  annotation-parsing ROUTING only (return/semantic parse + backend-validate
  paths, `mod.rs:3976/4096/4165/4222/4248`) — no codegen-shape switch, so the
  flag is safe for the seed.
- Stale-artifact trap (report's "additional friction"): the seed if-guard keys
  on ebnf.rs PRESENCE only; a stale ebnf.rs from an older pin fails the
  `cargo build` step with mass rustc errors and no diagnosis.
- The same seed commands WITHOUT `--bootstrap-mode` are documented in TWO more
  surfaces (the regex book `build-recipe.md` "Manual decomposition"; the
  integration contract § cold-zero-clone bootstrap) — all predate the
  `.5.i.1.t2` refusal guard (landed 2026-07-19/20) and were never re-synced.

## Fix design

`rust/Makefile` `regex_parser_bootstrap` (recipe-only; no Rust change — the
binary already exits nonzero):

1. **Fail-fast seed compound**: start the compound with `set -e;` so ANY
   failing seed step aborts the recipe with nonzero status (make stops at the
   failing step with its real error, not the misleading step-D message).
2. **`--bootstrap-mode` on seed step C** (the designed chicken-and-egg spelling
   per the target's own comment; annotation-routing-only, verified above).
3. **Stale-artifact diagnosis**: in the `else` (ebnf.rs present) branch, run the
   step-A build with an `|| { …actionable message…; exit 1; }` wrapper telling
   the consumer the artifact is stale and how to reseed
   (`rm ../generated/ebnf.rs` — or `rm -rf ../generated` — then re-run).

Docs lockstep (same slice): the regex book `build-recipe.md` manual
decomposition gains `--bootstrap-mode` + a "What can go wrong" row for the
REFUSED case; the integration contract's cold-bootstrap section gains the same
correction as a maintenance entry.

**End-to-end acceptance proof** (the report's verification note): with the
canonical `generated/` moved aside (cold-clone state), `make -C rust
SHELL=/bin/bash regex_parser_bootstrap` must complete exit-0 end-to-end; the
produced `generated/regex_parser.rs` must be **byte-identical** to the
canonical artifact (`1b5bdcf0` vintage — the regen-determinism tripwire per
`project_regen_canonical_path_only`); the seeded `ebnf.rs` is byte-compared
against canonical (`d4c257cf`) and the result recorded honestly either way.
Afterwards the canonical `generated/` set is restored and the dual-feature
`ast_pipeline` rebuilt (binary-coherence rule).
