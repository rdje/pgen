GRAMMAR-WELLFORMED.H.16.6c — THE SELF-REJECTION METRIC HAS TWO READINGS AND THEY DISAGREE
=========================================================================================

"the grammar self-rejects N of its own generated stimuli" is ambiguous, because the corpus
is GENERATED FROM the grammar: change the grammar and the corpus moves with it. Both
readings are recorded here, because a future session that regenerates stimuli and reads a
different number must be able to tell a real regression from a corpus vintage change.

  FIXED-CORPUS reading  — hold the PRE-(a+) corpus constant and score each grammar on it.
                          Correct for a before/after ledger: the corpus must not move if
                          the delta is to be attributable. This is the reading H.16.6a's
                          "18 -> 8" was measured under.
  OWN-CORPUS reading    — score each grammar against stimuli GENERATED BY THAT GRAMMAR.
                          This is the honest reading of "its OWN stimuli", and it is the
                          only one under which a NARROWING fix is not penalised by rows
                          its own generator would never emit.

corpora: `--generate-stimuli --count 200 --seed <s>`, deduped.
  5-seed  = seeds {0,7,42,123,999}   -> 1 000 unique
  16-seed = seeds {1,2,3,5,11,13,17,23,31,37,41,53,61,71,89,97} -> 3 200 unique

FIXED-CORPUS (the pre-(a+) 1 000-row corpus, held constant)
  pre-(a+) grammar  (dcc2e2d8)                      18 / 1000   <- H.16.6a's control, REPRODUCED
  HEAD    (2b5b26ea, arm (a+) landed)                8 / 1000   <- H.16.6a's result,  REPRODUCED
  arm1_close  (path/URL terminals exclude , ] } )   10 / 1000
  arm2_arrow  (arm1 plus = >)                       10 / 1000

  ⛔ 10 > 8 is NOT "the containment arm is worse". Direction is invisible in a net count:
     the per-input ledger reads widen=5 narrow=7 for BOTH arms. All 7 narrowed rows are
     inputs whose path/URL literal CONTAINS a delimiter (`./}.`, `~/}vP`, `/SH}2`, `/!,`,
     `file://,T`, `../]&}`, `~/bRk]`) — i.e. rows the un-narrowed generator emits and the
     narrowed generator, by construction, cannot. Scoring a narrowing fix on the corpus its
     own predecessor generated penalises it for rows that would no longer exist.

  HEAD                                  3                 15
  arm1_close  (, ] } ) )                0                  1
  arm2_arrow  (, ] } ) = >)             0                  0

  ⛔ The 5-seed zero for arm1_close is SEED LUCK at that sample size, not closure — the
     16-seed run finds one survivor, `@ PpgR : [ { http://PYJ=>  http://aFC } ]`, where the
     URL swallows the ARROW rather than a bracket. Only arm2_arrow, which also excludes
     `=` and `>`, reaches zero. Quoting the 5-seed zero alone would have been a claim the
     larger sample refutes.
