## 0. WHY THE FAILURES CAME ONE AT A TIME

`main()` runs the audits in sequence and `fail` aborts on the first one. So each blocker MASKED
every later blocker, and the only way to size the population was to fix and re-run, seven times.
⇒ "the gate is red for reason X" is never a complete statement about a fail-fast pipeline. The
count is not knowable until the last one clears.

⚠️ This also means the routing note in `.20` (2026-07-31, *"two fresh audit-phase blockers"*) was
not wrong so much as **bounded by the same mechanism** — two is what was visible from where it stood.

## 2. THE COMMON MECHANISM — THREE OF THE SEVEN ARE THE SAME DEFECT

Blockers 2, 3 and 7 are one shape: **an EXACT-SET or exact-string roster, maintained by hand, in a
gate nothing automatic runs.** A doc added to the tree does not join the roster, so the gate goes
red; and because the gate is operator-invoked, the red has no audience. Every one of these commits
was a legitimate, deliberate addition by a leaf doing its job. None of them was told.

Blockers 5 and 6 are a second shape: **a pinned assertion that outlived the decision it encoded.**
The Perl step was deliberately deleted; the README detail was deliberately moved. In both cases the
gate did not detect a regression — **it demanded one.**

Blocker 4 is a third: **the audit greps its own source**, so writing an explanatory comment about a
doc is indistinguishable from citing that doc badly. `.20` already recorded the self-referential
assertion class and measured *"exactly one site repo-wide … already written in the sound form"*.
⚠️ That measurement was over `assert_*` self-targeting calls; this is the same disease reached by a
different route — the file appearing in a grep FILE LIST — so it was outside that census by
construction, not missed by it.

Blocker 1 is a fourth: **one doctrine, two enforcers, different scopes** — `.20a`'s shape exactly,
on the axis `.20a` did not close. It aligned them on WHICH TREE (`--no-recurse-submodules`);
nothing aligned them on WHICH FILES or WHAT PATTERN.

## 3. THE FIXES — AND WHY NONE OF THEM IS "ADD IT TO THE LIST AND MOVE ON"

1. **Delegate, do not paraphrase.** `audit_markdown_repo_relative_paths` now CALLS
   `scripts/check_diagnostics_and_docpaths.sh` instead of re-deriving the rule. That enforcer is
   registered, runs from `.githooks/pre-commit` and in CI, documents its scope decision with its
   reasoning, and costs 0.32 s. The re-implementation it replaced was over-scoped in one direction
   and, in the other, matched a FIXED string containing ONE developer's username and ONE checkout
   location — so it could not have fired on a hosted runner at all. **That half failed in the
   PASSING direction, which is worse than the half that blocked.**
   ⛔ `CHANGES.md` is NOT edited. Append-only history is exactly the surface the doctrine exempts by
   design, and a changelog quoting a path creates no dependency on it.
2/3. **Deliberate admission, to `.1`'s standard** — reference counts measured before admitting, and
   the sort order taken verbatim from the audit's own output rather than guessed:
   `docs/CLAIM_VERIFICATION.md` 17 files / 46 mentions (it is the standing director directive named
   in the session prompt itself), `docs/DERIVED_STATE_CONTAINMENT.md` 14 / 46 (cited by layer-A
   `MEMORY.md`'s own header), `LIVE_DOCUMENT_SIZE_CONTAINMENT.md` a sibling of the already-listed
   `README_POLICY.md`.
4. **The stale comments now name the rehomed path** — the audit was RIGHT; the text was five months
   stale. ⚠️ I first dated these to March via `git log -L` and concluded the audit was "red at
   birth". **That was wrong and is retracted here**: `-L` traces line POSITIONS through history, not
   text. Running the audit's own pattern against the file AT the audit's birth commit returns ZERO
   hits, and `git log -S` on the exact strings dates all four to `c776bfac`, 2026-07-31.
5. **The Perl assertion is INVERTED and its population DERIVED.** Measured: `grep -il perl
   .github/workflows/*.yml` → **0 of 15**. The rule is no longer "these two may, those eight may
   not" but "no workflow may reintroduce Perl", which is a closed-population claim — so the
   population comes from `git ls-files`, and an empty population REFUSES rather than passing
   vacuously. A hand roster is what rotted in blockers 2, 3 and 7; it is not the fix for blocker 5.
6. **Reworded, not deleted.** The forbidden citation was explanatory prose that happened to sit
   inside the guarded section. The ruling's own text says the invariant is about INSTRUCTIONS and
   that history may name the file — so the sentence keeps its meaning and drops the internal path.
7. **The ENCODING was the defect, and rehoming the pins would not have fixed it.** All ten subjects
   are still documented on a live surface. ⚠️ My first census reported one as living NOWHERE; that
   was an artifact of exact-string matching — the repository path-inventory entry moved to
   `docs/book/src/developer-architecture.md:156` and was REWORDED on the way. So a pin on
   (one file × one sentence) breaks when EITHER moves, and both move routinely.
   ⇒ new `assert_documented_on_live_surface <identifier>`: it pins the **identifier** — a doc path
   or a make-target name, which is what the invariant is actually about — and looks for it anywhere
   on the live-doc surface set. A rehome or a rewording no longer produces a false red; deleting
   the subject still produces a true one. 10/10 pass.
