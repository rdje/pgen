⇒ A THRESHOLD, not a slope: 0.13 s at 300 and no result at 350 is a factor of >690 across
  one 50-paren step. SV ~10-11 logical frames/level x 350 = ~3 850, against the engine's
  4096-frame recursion ceiling. VHDL's cascade is shallower, so its cliff sits later —
  the SAME event at a different density, in a parser byte-identical to pre-campaign.

⛔ SV-CORPUS-GRAD.8c.3 fixed a SIGABRT here by routing embedding parses to a 256 MiB stack
  so the ceiling would return a clean E_PARSE_FAILURE. Today it returns nothing at all.

## IT IS A RUNAWAY SEARCH, NOT A DEADLOCK -- measured across dashboard snapshots

    lparen          2,089,390 -> 2,096,751 -> 2,104,128   (~7 400 per 250 ms tick)
    system_tf_call    508,487 ->   510,272 ->   512,109 -> 513,898

  Monotonically climbing => the process is doing WORK, not blocked on a lock or a cycle
  guard. That distinction matters: the fix is not "break a deadlock", it is "stop
  re-exploring".

## THE SHAPE OF THE WORK

  Every high-count rule is an ALTERNATIVE of the expression/primary cascade --
  tagged_union_expression, operator_assignment, streaming_concatenation,
  inside_expression, conditional_expression, empty_unpacked_array_concatenation, the
  tf_call family -- each retried ~500k-900k times. That is the signature of the whole
  alternative set being re-explored at every nesting level.

## THRESHOLD OR EXPONENTIAL? -- the fine-grained scan (director challenge, 2026-08-21)

  The first scan sampled 250/275/300 (fast) and 350/400 (timeout) and was called
  "a threshold, not a slope". That was NOT established: 690x across 50 parens is
  1.14^50, which a smooth exponential produces. Re-measured at 5-paren resolution:

    depth 305   0.13 s   accepted
    depth 310   0.13 s   accepted
    depth 315   0.14 s   accepted
    depth 320   > 150 s  NO RESULT
    depth 325   > 150 s  NO RESULT
    depth 330   > 150 s  NO RESULT

  >1000x across FIVE parens. An exponential steep enough for that (~4x per paren)
  would make 305 and 315 differ by ~10^6; they are identical at 0.13 / 0.14 s.
  => a genuine THRESHOLD between 315 and 320, now measured rather than inferred.

## THE ROOT CAUSE (ast_based_generator.rs), four links

  9307-9309   memoized_call records memo_recursion_entry_depth = rule_id_stack.len();
              this rule's own frame index is entry_depth - 1.
  9138-9142   note_recursion_block(frame_index) lowers recursion_block_floor.
  9365-9369   the memo REFUSES to cache a FAILURE when
                  memo_recursion_floor < memo_recursion_entry_depth - 1
              i.e. when the block came from a frame OUTSIDE this rule. Correct, and
              introduced by SV-CORPUS-GRAD.3.12 to fix real wrong-rejections.
  4100-4106   the whole-stack depth ceiling calls note_recursion_block(0) --
              "the depth ceiling is a fact about the WHOLE stack ... floor 0".

  => floor 0 makes the 9365 predicate true for EVERY rule at entry_depth >= 2, so one
     trip of the ceiling disables failure memoisation for the rest of the parse, and the
     packrat parse degenerates into exponential backtracking over the SV expression
     cascade's alternative fan-out. That is the 2 104 128 lparen calls.

  ASYMMETRY: every other guard arm taints only up to the ancestor owning the frame and
  "stops the propagation exactly at the ancestor that owns the frame". The depth ceiling
  is the ONLY arm that taints to 0, so its propagation never stops.
