⇒ A THRESHOLD, not a slope: 0.13 s at 300 and no result at 350 is a factor of >690 across
  one 50-paren step. SV ~10-11 logical frames/level x 350 = ~3 850, against the engine's
  4096-frame recursion ceiling. VHDL's cascade is shallower, so its cliff sits later —
  the SAME event at a different density, in a parser byte-identical to pre-campaign.

⛔ SV-CORPUS-GRAD.8c.3 fixed a SIGABRT here by routing embedding parses to a 256 MiB stack
  so the ceiling would return a clean E_PARSE_FAILURE. Today it returns nothing at all.

## IT IS A RUNAWAY SEARCH, NOT A DEADLOCK -- measured across dashboard snapshots

    lparen          2,089,390 -> 2,096,751 -> 2,104,128   (~7 400 per 250 ms tick)
    system_tf_call    508,487 ->   510,272 ->   512,109 -> 513,898

  Monotonically climbing => the process is doing WORK, not blocked on a lock or a cycle
  guard. That distinction matters: the fix is not "break a deadlock", it is "stop
  re-exploring".

## THE SHAPE OF THE WORK

  Every high-count rule is an ALTERNATIVE of the expression/primary cascade --
  tagged_union_expression, operator_assignment, streaming_concatenation,
  inside_expression, conditional_expression, empty_unpacked_array_concatenation, the
  tf_call family -- each retried ~500k-900k times. That is the signature of the whole
  alternative set being re-explored at every nesting level.
